## 1. 结论

| 打开方式 | 旧文件 | 新文件 | 说明 |
| --- | --- | --- | --- |
| **读开**（`ctx.sessionQuery.readSession()`，列表/导出/查询路径） | 逐字节不变 | **不产生** | 迁移只在内存发生 |
| **写开**（`ctx.sessionPersistence.open(id, 'write')`、headless 采纳/resume、TUI 继续会话） | 逐字节不变 | 发布 `session.v4.jsonl.zstd` 后继 + `session.lock` | 非原地改写；旧代文件保留 |

→ 迁移是**逐会话、按需**的。计划里"打开即改写"的口径应改为"首次写开时发布 v4 后继、源文件保留"。
v0（无版本后缀）与 v3 两种旧格式**都实测了写开**；读开只在 v3 上实测（同一 persistence 读路径）。

## 5. 上游 README 原文（安装产物）

`node_modules/@deepseek-ai/dsh-session-persistence-jsonl/README.md:82`：

> For historical input, a read open decodes and migrates the source once, validates the current logical result, and returns it without publishing a successor. A write open reuses that revision-keyed preparation when available, or performs the same preparation, then encodes a same-directory temporary file in bounded chunks, verifies it in a Worker Thread, rechecks the source revision, and publishes the current successor without overwrite before returning. The source remains byte-identical.
