# dsh-plugins 回归测试自动化（确定性交付闸门 + 按需 PTY 冒烟）

> 施工图：`docs/regression-test-automation-plan.md`（v2，用户 2026-09-11 批准；含逐阶段改动面、断言清单与勘误）。
> 本 spec 是给 tracker 的合成视图，不含文件路径；路径与命令以施工图为准。

## Problem Statement

本轮的 dsh 0.1.5-rc.1 升级暴露了 8 类真实回归，**没有一类是现有单元测试能拦住的**：profile 重复 loader id 要靠手工逐 id 计数、会话事件接口被移除要靠冷启动崩溃才发现、seeded 子会话预览失效要靠真实 fixture 探针、首轮 bash 的 schema/registry 时序要靠观察真实模型会话日志、部署位副本与仓库漂移要靠手工比对 sha、会话格式迁移不可逆却只靠事后盘点。现有自动化资产（单元测试、零 LLM 冒烟、若干探针、行为基线 runner）本身是够用的，但它们**散落各处、没有统一入口与退出码、没有版本闸门、部分写死了本机绝对路径**——结果是「改完不知道有没有踩回归」，只能靠每次手工重跑一长串命令与现场观察。

更麻烦的是，这些手工闸门里有一半依赖真实模型调用，既花额度、又受 sampling 波动影响（同一条回归在 5 个真实会话里只有 2 次撞上），无法作为每次改动的门禁；而另一半（组合装配、插件时序）根本没有确定性覆盖手段。

此外，本仓库同时维护稳定侧与开发侧两套组合：稳定侧被刻意钉在旧宿主上，其单测依赖旧语义，**不能**并列进同一条测试链，但这一点此前没有写进任何文档，容易让人误以为「测试全绿 = 两侧都安全」。

## Solution

给开发侧建**一条命令的确定性交付闸门**，并把本轮踩过的坑逐项固化成断言。

闸门按「能确定就不烧额度」分层：静态检查（类型、单测、测试清单一致性）→ 零 LLM 组合闸门（组合装配、工具集合、部署位一致性、宿主与会话格式版本、反劫持）→ **脚本化假模型行为层**（在真实 agent loop 里回放手写脚本，零额度、可进 CI）→ 进程内 app 层（假终端驱动 TUI，进单测）→ 真实模型基线（按需）→ 真实 PTY 冒烟（独立脚本、按需、不接发版）。每一层都产出可归档的结构化报告，记录宿主版本、会话格式版本、组合与部署位 sha、git HEAD，使「宿主升级后哪些基线失效、需要重采」成为一个可机器回答的问题。

闸门默认跑一个**自持的闸门组合**（只依赖本仓库与公共 registry 上的宿主），使它在任意 checkout 与 CI 上都能跑；交付前用 `real` 模式把**真实开发 profile 运行期渲染**进隔离 home，验证的就是真实组合，且对用户的 `~/.dsh` 零写入。部署位一致性作为前置断言，缺席与陈旧分开表达、都可显式豁免，但豁免必须写进报告并打印警告——豁免绝不静默变成绿灯。

稳定侧的任何文件不修改、不纳入闸门。

## User Stories

1. 作为本仓库的维护者，我希望有一条命令跑完确定性回归，以便改完代码后能立刻知道有没有踩回归，而不必记住一长串散装命令。
2. 作为本仓库的维护者，我希望这条命令的退出码能区分「断言失败」与「环境前置不满足」，以便在 CI 与本机得到不同的处置。
3. 作为本仓库的维护者，我希望每次运行的结论落成可归档的结构化报告，以便跨轮次对比、而不是被下一次运行覆盖。
4. 作为本仓库的维护者，我希望报告里逐条列出断言及其证据，以便失败时直接定位到机制，而不是从 stdout 里翻文本。
5. 作为本仓库的维护者，我希望报告记录宿主版本、会话格式版本、组合与部署位 sha 以及 git HEAD，以便知道这一次结论是对哪套东西下的。
6. 作为本仓库的维护者，我希望闸门在宿主版本或会话格式与记录不符时拒绝运行，以便不会拿着失效的基线得出「通过」。
7. 作为本仓库的维护者，我希望真实模型基线的归档规范化，以便换宿主后明确知道哪些数字需要重采。
8. 作为本仓库的维护者，我希望部署位副本与仓库内容的一致性成为前置断言，以便「仓库绿灯但部署位是旧的」这种假绿不再发生。
9. 作为正在改组合配置的维护者，我希望在尚未同步部署位的中间态下能显式豁免这一条检查，以便不必为了跑一次其余检查而先去同步。
10. 作为本仓库的维护者，我希望任何豁免都出现在报告里并在终端醒目提示，以便豁免不会被误读为通过。
11. 作为本仓库的维护者，我希望在部署位根本不存在（如 CI、别的 checkout）时能把「缺席」与「陈旧」分开表达，以便报告不产生含混的豁免理由。
12. 作为本仓库的维护者，我希望闸门不自动同步部署位，以便测试不会去写用户的环境。
13. 作为本仓库的维护者，我希望闸门在隔离的临时 home 里运行，以便它不污染我真实的会话、设置与 profile。
14. 作为本仓库的维护者，我希望闸门在任意 checkout 上可跑，以便换目录、开 worktree 或上 CI 时不必改脚本。
15. 作为本仓库的维护者，我希望仓库内不再有写死的本机绝对路径，以便这类漂移不会随新脚本继续扩散。
16. 作为本仓库的维护者，我希望闸门在跑真实组合前把 profile 里指向本仓库与相邻仓库的路径按环境渲染，以便既不修改我的 profile 又验证到真实组合。
17. 作为本仓库的维护者，我希望 `real` 模式在缺少相邻仓库时明确报环境错误而非静默降级，以便「验证了真实组合」这句话可信。
18. 作为本仓库的维护者，我希望闸门在多个终端同时运行时串行化，以便共享依赖树的代际翻转不会让两个运行互相污染。
19. 作为本仓库的维护者，我希望闸门断言依赖树解析到的宿主代与记录一致，以便「跑的是哪一代插件」不再靠猜。
20. 作为本仓库的维护者，我希望配置装配层有一处闸门，把逐 loader id 的重复计数变成断言，以便重复挂载这类致命配置错误在启动前就被拦住。
21. 作为本仓库的维护者，我希望零 LLM 的组合冒烟覆盖「工具集合与首轮锚定」「降级路径」「seeded 预览」三件事，以便它们进入统一入口而不是各自手跑。
22. 作为本仓库的维护者，我希望 seeded 预览的 fixture 随仓库入库并自建其工作目录，以便探针不会因为某个真实会话被清理而静默失效。
23. 作为本仓库的维护者，我希望闸门能跑一个脚本化的假模型，以便在没有额度、没有网络的情况下覆盖真实 agent loop 的时序类回归。
24. 作为本仓库的维护者，我希望假模型只作为补丁覆盖层注入，绝不进入部署位或组合行，以便真实会话永远不会被假模型劫持。
25. 作为本仓库的维护者，我希望闸门断言组合中不出现假模型，以便这条遏制规则本身也被机器守住。
26. 作为本仓库的维护者，我希望假模型层的场景脚本是手写且与具体回归一一对应的，以便每个脚本都在锁定一个明确的不变量。
27. 作为本仓库的维护者，我希望每个场景脚本头部注明它锁定的不变量与来源，以便将来判断它是否还有价值。
28. 作为本仓库的维护者，我希望假模型层能复现「首轮 bash 调用参数不满足 schema」这条回归，以便它能像修复前一样先红后绿。
29. 作为本仓库的维护者，我希望这条红绿证据被留档，以便证明闸门真的拦得住它、而不是碰巧通过。
30. 作为本仓库的维护者，我希望假模型层的首个请求就断言路由落在假模型上，以便「忘了改路由导致打到真实 provider」这类零成本层最怕的失败模式当场暴露。
31. 作为本仓库的维护者，我希望假模型层关掉会自动并发调用模型的辅助功能，以便场景脚本的执行顺序是确定的。
32. 作为本仓库的维护者，我希望假模型层断言只读会话事件与副作用，以便结论可核对、不受模型措辞影响。
33. 作为本仓库的维护者，我希望 TUI 的终端依赖可以在构造时注入，以便在进程内用假终端驱动真实的 app 层。
34. 作为本仓库的维护者，我希望终端恢复契约（进入/退出备用屏、光标恢复）成为断言，以便退出路径被改坏时测试变红。
35. 作为本仓库的维护者，我希望冷启动首帧、状态行、按键语义与选择器流程都有进程内断言，以便这些高频回归不必依赖人工看屏幕。
36. 作为本仓库的维护者，我希望复制行为只在远程会话分支下断言，以便测试既不写系统剪贴板也不会恒绿。
37. 作为本仓库的维护者，我希望这些 app 层断言进入日常单测，以便它们成本低到可以每次都跑。
38. 作为本仓库的维护者，我希望有一份按需的真实 PTY 冒烟，以便换宿主或大改 TUI 时能自动验证真实组合的启动、命令、删除会话、切换模型与退出。
39. 作为本仓库的维护者，我希望 PTY 冒烟把终端输出还原成屏幕缓冲后做结构化断言，以便断言不依赖字体、DPI 与终端实现。
40. 作为本仓库的维护者，我希望 PTY 冒烟量化首帧延迟与分块间隔，以便「流式是否顺滑」有数值而不是印象。
41. 作为本仓库的维护者，我希望 PTY 冒烟明确不接发版流程，以便它不会因为需要真进程与 PTY 环境而拖住发版。
42. 作为本仓库的维护者，我希望 PTY 冒烟有独立入口且不被主闸门引用，以便两者可以各自演进。
43. 作为本仓库的维护者，我希望真实的回退（rewind）落盘路径至少被某层自动化覆盖，以便这条曾经出过问题的路径不会完全依赖人工。
44. 作为本仓库的维护者，我希望视觉与体感类检查被明确区分为「可量化」与「只能参谋」，以便它们不会变成不可复现的通过标准。
45. 作为本仓库的维护者，我希望判定模型读图的结论只写进报告、不产生退出码，以便它不会污染闸门的可信度。

47. 作为本仓库的维护者，我希望 CI 上跑得起来的层尽可能多，并且不依赖任何密钥，以便闸门在合并前就能拦住回归。
48. 作为本仓库的维护者，我希望发版流程在打包前调用闸门且永不带豁免，以便发布总是发生在部署位一致的状态下。

53. 作为本仓库的维护者，我希望已失效的 CI 触发路径被修正，以便工作流真的会触发、且指向仍然存在的目录。

## Implementation Decisions

**范围与边界**

- 闸门只覆盖开发侧：开发 profile、开发组合、开发侧脚本与两个自研插件。稳定侧的组合文件、运行时、部署位副本与既有测试**一律不修改、不纳入**，理由（其单测绑定旧宿主语义）写进文档。
- 不改动其他仓库（relay、长期记忆）；真实组合模式把它们当作**运行期依赖**，按环境变量渲染路径，缺则报环境错误。

**入口与退出码**

- 单一入口脚本，接受分层选择（哪些层跑）、组合选择（自持闸门组合 / 真实组合）、报告输出路径，以及两个互斥语义的豁免开关。
- 退出码三态：全过、任一断言失败、环境前置不满足。
- 豁免只有两种，且都必须写进报告的豁免数组并在终端打印醒目警告：部署位陈旧、部署位缺席。发版路径传递的组合模式固定为真实组合，且永不携带任何豁免参数。
- 闸门不自动同步部署位；同步仍是显式动作。

**运行态与隔离**

- 默认运行一个**自持的闸门组合**：只挂宿主 base 与本仓库的 TUI 入口、命令插件、回退插件，加上目标 preset；不依赖任何相邻仓库，因此任意 checkout 与 hosted CI 可跑。
- `real` 模式**运行期渲染**真实开发 profile：读取源 profile 文本，按环境变量（本仓库根、相邻两仓库根，默认取相邻 checkout）替换其中的绝对路径，物化到隔离临时 home，连同设置副本与会话根；源 profile 只读。报告同时记录源 sha 与渲染后 sha。
- 所有层的写入一律指向临时 home 或临时目录，真实 home 零写入（宿主启动对 profile 的规范化回写落在副本上，属接受的幂等写，报告记录其 sha）。
- 闸门持有一个仓库本地锁文件以串行化并发运行；并断言依赖树解析到的宿主版本等于版本清单记录的版本。

**路径可移植性**

- 仓库内资产（preset 根、补丁插入的模块名、driver 路径）一律由**模块自身位置**推导，不再写死绝对路径；补丁插入项用相对补丁文件的写法，配置值用「环境变量优先、内置默认兜底」的表达式。
- 宿主侧包**使用裸包名导入**：实测其 `exports` 映射只暴露入口与 `./src/*`，深路径导入会被拒绝；裸包名在仓库任意位置解析成功。任意 checkout 的前置条件是执行仓库既有的链接脚本（把仓库的宿主依赖作用域指向全局安装）。
- 唯一需要显式推导宿主依赖目录的场景是**不在依赖声明里的传递依赖**（PTY 与终端模拟器）：按宿主安装锚点推导并给出清晰报错，不硬编码解释器路径。
- 历史结果文件里内嵌的绝对路径属记录内容，不改；发行脚本里的稳定运行时默认值属部署配置，不改。

**版本闸门**

- 新增单一来源的版本清单：宿主版本、会话格式版本、部署位文件 sha 表、各真实模型基线的摘要与采集时的宿主版本。
- 装配层强制比对清单；真实模型层在检测到宿主或格式变化时拒绝运行并提示重采基线。
- 测试清单一致性也进闸门：测试脚本声明的文件必须存在且可运行。

**组合装配断言**

- 对两个 profile（开发 profile 与隔离渲染副本）分别做配置导出，断言退出码为零且**逐 loader id 递归计数为一**（配置导出本身不检测重复 id，因此必须单独断言）。
- 断言首轮锚定工具对、沙箱 bash 与工具数符合期望、seeded 预览探针全绿（含「seeded 会话用快路径读取必被拒」这条红线仍在）。
- 断言组合导出中不出现假模型的 provider 名或模块路径。

**假模型行为层**

- 形态：进程内组合（载入宿主 profile 的 bundle 层 + 补丁覆盖），用宿主既有的适配器注册接口注入一个**脚本化回放适配器**，然后按既有 driver 范式显式创建 agent、挂载目标 preset、发送用户消息、等待空闲，再从会话事件中断言。
- 适配器只需实现流式方法；其余方法有可用的默认实现。脚本以「轮次 → 分块序列」表达，工具调用参数为原始 JSON 字符串，分块顺序照生产适配器的收尾形状（各块收尾 → 用量 → 结束）。
- 路由必须由 driver 显式传入（每 agent 的选项 + 选择安装），**不能**只依赖组合行的默认模型：设置用户层会覆盖组合行，副本里带设置文件时不可靠。
- 覆盖层内关闭会自动并发调用模型的辅助功能（标题生成），并断言首个请求头的模型配置等于假模型路由。
- 场景脚本一文件一场景，导出场景标识、锁定的不变量、轮次与断言函数；断言只读会话事件（请求头、工具调用参数、工具结果错误位、轮次结束）与文件系统副作用。
- 首批场景：首轮 bash 调用不带描述参数（复现并锁定那条回归）、提升后沙箱 bash 可见与压缩后回退、V3 会话恢复后的请求头含路由发现工具、委派策略（省略路由继承父路由、集合外路由被拒）。
- 假模型只出现在覆盖层：不进入 preset 行、不进入任何 profile 与部署位；使用独立 provider 名，不遮蔽真实 provider。

**进程内 app 层**

- 给 app 的构造选项增加一个可选的终端注入项，默认走真实终端实现（全进程只构造一次 app，不存在同进程重建终端的需求，因此不做工厂）。
- 新增假终端测试件：实现完整的终端接口（含输入排空）、捕获写入帧、可注入按键、固定列行数。
- 断言：冷启动首帧含路由与 preset、状态行字段、单次与双次中断键的退出语义、选择器流程返回选中值、退出路径的终端恢复序列（进入与退出备用屏、光标恢复）。
- 复制相关断言必须走远程会话分支，否则要么真去写系统剪贴板、要么断言恒绿——此坑写进测试注释。
- 明确不覆盖（属命令注册闭包，须 PTY 层）：模型切换、强度切换、会话列表、删除会话、恢复、退出、回退命令。

**真实 PTY 冒烟（独立、按需）**

- 独立脚本 + 薄壳，主闸门**不引用**它；用真实开发 profile（渲染副本）、固定 PTY 尺寸与终端类型，把输出喂给无界面的终端模拟器得到屏幕缓冲。
- 断言的依据是屏幕缓冲与副作用：启动到首帧、会话列表、删除会话后存储变化、切换模型后下一次请求头的路由、退出码与备用屏退出序列、归一化后无转义残留与不超列宽。
- 时间维度用量化指标：首帧延迟与分块间隔的分位数；重绘上界用原始输出中清屏序列的出现次数（跨进程读不到宿主内部的重绘计数器）。
- 首次验收由人工在普通 shell 手跑（本会话沙箱无法创建 PTY）；CI 侧以手动触发的常驻入口作为长期形态。
- 明确不作为发版门禁。

**视觉与体感（参谋层）**

- 几何/文本类用屏幕缓冲程序化断言；真实像素渲染（字体、DPI、字形、图片协议）与原生剪贴板实际写入只作人工或参谋。
- 判定模型只能做分诊与「从快照提出应断言的文本/结构」，结论只写报告、不产生退出码；整屏截图不得进入判定链。
- 若要使用判定路由，必须实测记录「能读图」的结论（模型、日期、结论），不得据配置里声明的输入模态推断上游能力。

**报告**

- 结构化报告含：闸门版本、起止时间、git HEAD 与是否脏、宿主版本、会话格式版本、组合模式与源/渲染 sha、部署位比对结果（含陈旧/缺席状态）、逐层的逐条断言（含状态、证据、明细）、豁免数组、汇总计数。
- 报告默认归档到仓库既有实验目录约定下，文件带日期。

**清理与收尾**

- 清理可证明由探针产生的残留：目标项目目录下的行为基线会话与轨迹会话、本轮票据的临时目录；清理前打印完整清单，不触碰其它前缀与会话目录。
- 行为基线与轨迹 runner 改为写隔离会话根，确保清理后不再生长。
- 修正失效的 CI 触发路径并指向仍存在的目录，同时把脚本内的 preset 路径参数化。
- 统一测试脚手架：把自带引导桩的测试文件并入共享桩；stable 侧的那份属冻结副本，不动、差异保留并注明。
- 施工图中被实测证伪的事实就地校正（残留会话数量、稳定运行时位置、依赖包归属、接口成员数、字段名、命令注册位置等）。

## Testing Decisions

**什么算好测试**

只断言外部可观察行为与其原始证据：配置导出里的 id 唯一性与挂载形状、会话事件里的请求头与工具调用/结果、文件系统 sha 与目录变化、进程退出码与终端控制序列。每条断言必须指向可核对的原始位置；不引用模型自述、不把渲染文本当机制证据、不比对模型措辞。

**测试 seam（尽可能少，取最高处）**

- **装配 seam**：配置导出 + 逐 id 计数，加零 LLM 组合冒烟。覆盖「组合是否装配得起来、工具面是否正确」，不覆盖行为。
- **行为 seam（新增，零额度）**：真实 agent loop + 脚本化假模型。这是本次新增的最大覆盖缺口补丁——它补在「假事件单测覆盖不到真实时序」与「真实模型验证是概率性的」之间。
- **app seam（新增，零额度）**：进程内真实 app + 假终端。覆盖终端生命周期与交互流程，不启动进程、不需要 PTY。
- **真实组合 seam（按需）**：真实 PTY + 真实 profile；覆盖只有真进程才有的路径（命令注册闭包、回退落盘、退出序列）。
- **真实模型 seam（按需）**：既有行为基线与路由探针，仅在其宿主版本与记录一致时运行。

**被测模块**

组合层各插件（首轮锚定、指令提示、bash 换用、技能检索、压缩纪元、自定义 bash）；TUI 的会话预览读取路径、终端生命周期与交互流程；命令注册闭包经 PTY 层覆盖；委派工具的路由策略经假模型层与真实模型层分别覆盖。假模型与假终端本身只作为测试件，不进入交付路径。

**先例**

仓库已有同形状的资产可直接沿用：进程内组合引导（零 LLM 冒烟）、按补丁覆盖层注入 driver 的探针、按会话事件断言的模型选择探针、按批次记录的行为基线 runner。新测试沿用同一形状，不另创断言风格。

**不做的测试**

不做整屏像素 golden（备用屏重绘使其维护成本高于信号价值）；不把依赖额度或网络的真实路由探针放进 CI；不把口径类措辞统计当硬指标；不测真实 provider 的失败分类（留给按需的真实模型层）；不测 Windows 行为。

## Out of Scope

- 稳定侧任何文件、运行时、部署位副本与测试的改动；不为稳定侧建跨代闸门。
- 其它仓库（relay、长期记忆）的代码适配与协议变更。
- 角色化模型路由（按用途固定模型）与任何自研路由/适配层。
- 真实 provider 的网络与错误分类测试、sampling 质量评估。
- 整屏像素回归、网关字体的渲染正确性、终端差异（iTerm / Terminal.app / tmux / SSH）的自动化。
- 把 PTY 冒烟接进发版门禁。
- 给命令注册闭包所在的运行时增加注入 seam（本轮接受该覆盖缺口，仅由按需 PTY 层覆盖）。
- Windows 行为与 CI。

## Further Notes

**事实来源（第一方，均为 2026-09-11 实测）**

- 宿主 `@deepseek-ai/dsh@0.1.5-rc.1` 来自公共 registry（可匿名安装）；全局、依赖作用域与依赖树农场三处版本一致。
- 本机不存在 `0.1.5-rc.2` 的任何痕迹（无缓存包、无备份、无工作树、无票据），上一轮的 rc.2 升级未落地；本闸门的版本基线钉在 rc.1。
- 真实开发 profile 内共 10 条绝对路径，其中 6 条指向另外两个仓库——这是「自持闸门组合 + 运行期渲染」双形态的唯一原因。
- 部署位 preset 的 8 个生产文件与仓库逐字节一致（测试类文件本就不在部署位）。
- 宿主包 `exports` 映射只暴露入口与 `./src/*`：深路径导入被拒、裸包名可用。
- PTY 与终端模拟器是宿主内嵌依赖（非直接声明），本机可加载；但 PTY 创建在本会话沙箱内被拒，属未验证项，由人工首跑确认。
- TUI 存在硬性 TTY 门（标准输入输出非 TTY 即拒启动），因此管道输入不可作为 PTY 的退路。

**开放问题**

- 回退落盘路径位于命令注册闭包内且受 TTY 门约束，进程内两层都够不到：本轮接受该缺口（仅按需 PTY 层覆盖），不为此给运行时增加注入 seam；若将来出现相关事故再评估。
- hosted CI 能否在干净 runner 上装起宿主并跑通组合层，是实践阶段要验证的事实而非当前假设；不行则退回自托管。
- 隔离渲染副本与真实部署态的逐字节等价性只在 `real` 模式下成立，其余情况依赖三层 sha 记录兜底。
